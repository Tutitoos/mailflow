# Contribuir a Mailflow

Mailflow es actualmente un proyecto personal en fase de planificación. Las contribuciones pequeñas y alineadas con el alcance son bienvenidas.

## Antes de proponer cambios

- Busca primero Issues abiertas y cerradas para evitar duplicados.
- Abre una Issue para todo cambio implementable y completa objetivo, alcance, tareas, aceptación, validación, dependencias, riesgos y exclusiones.
- Mantén el alcance personal y self-hosted.
- No añadas servicios centrales, telemetría obligatoria o funciones premium.
- No incluyas mensajes, cuentas, tokens, capturas o datos personales reales.

## Pull requests

- Crea una rama `<category>/<issue-number>-<descripcion>` desde `origin/main`.
- Explica el problema y el comportamiento esperado.
- Mantén cada PR centrado en un único objetivo.
- Incluye `Closes #<issue-number>` para cerrar su Issue principal al fusionarse.
- Añade o actualiza pruebas cuando exista código afectado.
- Actualiza la documentación si cambia un contrato o decisión.
- Confirma que no se han incluido secretos ni datos personales.

Al contribuir aceptas que tu trabajo se publique bajo la licencia AGPLv3 del proyecto.

Las PR automáticas de Dependabot no necesitan una Issue adicional. No publiques vulnerabilidades sensibles como Issues: sigue el canal indicado en `SECURITY.md`.
